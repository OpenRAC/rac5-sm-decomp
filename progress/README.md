# Scoped progress snapshot

[`status.json`](status.json) is generated by [`tools/progress_status.py`](../tools/progress_status.py)
after the private boot and level-program gates pass. It records **one accepted
16-byte C function in the 498,900-byte boot `.text`**, plus **two shared
C functions (8 + 72 bytes) at twenty numbered level placements**. These count
as two authored functions, not forty independent matches. Two other exact C
shapes remain provisional controls. `FRONTEND.REL` and `LEVEL_01.REL` have exact complete-file assembly
replacement and measured relocated-image baselines. Their original non-code
bytes are still inputs, and assembly equality is not C progress.

The 21 level code intervals total 36,341,888 **bytes by placement**. They are
candidate code intervals, not verified function sizes or unique game code.
`LEVEL_15.REL` and `LEVEL_21.REL` already have identical complete interval
hashes; smaller shared functions may occur elsewhere. `overall_percent` is
therefore `null`. The only percentage in the snapshot is explicitly scoped to
the boot `.text`: 16 / 498,900 bytes (0.00320706%).
The [function-boundary and deduplication audit](../docs/LEVEL-FUNCTION-INVENTORY.md)
now records 124,356 possible entry intervals, 74,051 stronger bounded
candidates and an exact-duplicate upper bound of 33,168,892 candidate bytes.
Relocation-masked groups remain review leads, not counted progress.
An independent R5900 Ghidra pass agrees with **91,350** of those candidate
boundaries. The data-target and closed local-callgraph checks retain **2,416
shared template leads**, including one 32,796-byte body across all twenty numbered
levels. The [audit guide](../docs/LEVEL-FUNCTION-INVENTORY.md) explains why
these are useful deduplication worklists but still not an exact unique-code
denominator.
The optional Ghidra body-range pass flags **1,590** candidate starts inside
another body; **1,209** also have a direct branch or jump from that same body.
A full-module pass classifies all 1,590 as review leads, including **21**
newly called function entries and **229** contiguous cases without a recovered
indirect reference. These remain candidate evidence, not counted C progress.
The split-body audit selects **6,245** corroborated segments inside **3,729**
oversized candidate intervals, leaving 294,836 surrounding body bytes unique.
Its **23,446,344-byte** result, including conditional target-graph matches
for zero-filled local data and placement-checked partial families, is a
conditional deduplication scenario, not a verified unique-code denominator.
An [optimistic masked-shape audit](../docs/LEVEL-FUNCTION-INVENTORY.md#optimistic-relocation-masked-shape-scenario)
also measures **7,060,508 candidate bytes** when identical masked bodies are
grouped across levels while repeated bodies inside one level stay separate.
That is a useful aggressive research scenario, not an accepted progress total.
An additional [context/data review](../docs/LEVEL-FUNCTION-INVENTORY.md#repeated-shapes-with-code-context-and-data-anchors)
retains 3,727 repeated-shape families after global collision and final-callee
checks and gives a **19,872,400-byte conditional
scenario**. This too remains a structural worklist, not counted C progress.

To refresh the snapshot with your own lawful pinned USA image and local tools,
run the [boot gate](../docs/BOOT-TRIAL-GATE.md), the
[level-program gate](../docs/LEVEL-PROGRAM-GATE.md) and the
[shared level C gate](../docs/LEVEL-C-WITNESS.md), then:

```sh
python tools/level_function_inventory.py --write baserom/SCUS_976.15.iso
python tools/level_function_inventory.py --check
python tools/level_ghidra_crosscheck.py --write
python tools/level_translation_families.py --write baserom/SCUS_976.15.iso
python tools/level_flow_ranges.py --write
python tools/level_full_module_flow.py --extract baserom/SCUS_976.15.iso
# Run the private full-module Ghidra pass described in tools/ghidra/README.md.
python tools/level_full_module_flow.py --write baserom/SCUS_976.15.iso --ghidra-dir build/level-functions/full-ghidra
python tools/level_full_module_flow.py --check
python tools/level_split_dedupe.py --write baserom/SCUS_976.15.iso --ghidra-dir build/level-functions/full-ghidra
python tools/level_split_dedupe.py --check
python tools/level_shape_scenario.py --write baserom/SCUS_976.15.iso
python tools/level_shape_scenario.py --check
python tools/level_context_translation.py --write baserom/SCUS_976.15.iso
python tools/level_context_translation.py --check
python tools/progress_status.py --write
python tools/progress_status.py --check
```

The Ghidra cross-check also requires private metadata exports; its
[reproduction guide](../tools/ghidra/README.md) gives the command. Progress
`--write` requires the ignored private gate receipts. CI can run `--check`
without game data; it detects drift in the committed catalogues, accepted C
source and reported evidence. CI does not repeat the proprietary-tool builds.

This is **not an objdiff v2 report** and is not uploaded to ByteMatch. ByteMatch
ingests an [objdiff report artifact from a successful default-branch push](https://github.com/Veradictus/ByteMatch/blob/master/docs/getting-started.md).
Publishing a game-wide artifact now would imply a qualified function inventory
and shared-code denominator that this project has not established. Those
remain the next reporting gates.
