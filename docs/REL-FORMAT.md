# USA PS2 level modules: measured SNR2 metadata

The verified `SCUS_976.15` disc has 21 `LVL/*.REL` files: `FRONTEND.REL` and
20 numbered level modules. All begin with `SNR2`, a **SN ProDG relocatable
module format**, rather than an ELF header. The field names used by
[`tools/rel.py`](../tools/rel.py) follow the public
[SNR2 loader by emoose](https://github.com/emoose/re4-research/blob/master/prodg-rel.py)
(BSD-3-Clause). The parser itself was written here and tested against all 21
files; this is a format reference, not imported game code.

For this USA image, the first 60 bytes contain the signature, relocation-table
offset and count, symbol-table offset and count, and a file-size field at
`0x2C`. Every file's declared size equals its actual size. Each relocation
record occupies 12 bytes; the relocation table ends exactly where the symbol
table begins. The 21 files hold **85,694 named-symbol relocation records**: type 2 (483),
type 4 (73,765), type 5 (5,329) and type 6 (6,117). Every recorded symbol
index is in range. These are structure checks, not relocated game images.

## Packed local fixups and the boot loader

The pinned boot's `MODULE_LoadModule__FPCc` (`0x01E8F218`) loads a REL and
passes its **128-byte-aligned** in-memory address to `snDllLoaded`
(`0x01E9BB58`). The latter validates the SNR header, converts its pointer
fields to in-memory addresses, and calls the relocation routine at
`0x01E9B5A8`. That routine processes **two** tables: first a compact stream
pointed to by the header field at `0x34`, then the 12-byte named-symbol table
at header field `0x04`. The compact stream is therefore not a replacement for
the named table.

Each compact-stream descriptor uses its low two bits for the operation and
the upper six bits for a four-byte-aligned site delta. A zero delta is
followed by a 32-bit absolute module offset; offset zero terminates the
stream. Operation 1 (HI16) looks ahead to a later operation 0 (LO16) for its
paired low half, without consuming that later descriptor. Operations 2 and 3
are 26-bit jump and 32-bit word fixups respectively. These interpretations
were checked against the boot's relocation helper at `0x01E9AE08`; the
catalogue **counts sites but never applies fixups**.

All 21 modules have a stream at the end of their symbol table. The scanner
reaches a terminator at the exact file end in each module, validates that
every site is aligned and within the pre-relocation-table payload, and finds
a following LO16 site for every HI16. It counts **833,103 packed fixup sites**
across placements: 189,411 HI16, 262,333 LO16, 303,359 26-bit and 78,000
32-bit. These are relocation events, **not unique code bytes, functions, C
matches or progress**. `config/levels/modules.tsv` records both kinds of
relocation separately and is generated by `tools/rel.py`.

In one isolated PCSX2 run (`d75a0ad`, pinned `SCUS_976.15` image, game CRC
`8661F7BA`), `FRONTEND.REL` occupied a session-specific base of `0x00F97B80`
in the `modules` table. The in-memory SNR2 header retained its declared size
of `0x001F52BA`; its relocated pointers equaled that base plus their file
offsets. The table's entry-point value, `0x00FB0F90`, equaled the base plus the
catalogued `lib_main__FiPPc` offset `0x19410`. The local calculation predicted
the observed runtime words at **12 packed sites** (three each of HI16, LO16,
26-bit and 32-bit) and **four named-symbol sites** (one each of types 2, 4,
5 and 6). No instruction words or RAM dumps are committed. This is a sampled
runtime cross-check, **not** complete relocated-image equality; another run
or level may use a different base.

The symbol tables expose **41 nonzero-address exports**: one
`lib_main__FiPPc` in each module and `G_wadFilename` in each of the 20 level
modules. `G_wadFilename` is data, so an export is not automatically a function.
The tables in [`config/levels/`](../config/levels/) contain module hashes and
these exported names with **module-relative offsets**, not linked RAM
addresses. Regenerate or verify them with:

```sh
python tools/rel.py inspect baserom/SCUS_976.15.iso
python tools/rel.py inspect baserom/SCUS_976.15.iso --boot baserom/SCUS_976.15
python tools/rel.py catalogue baserom/SCUS_976.15.iso
python tools/rel.py catalogue baserom/SCUS_976.15.iso --write
```

The next research step is to capture a level REL base and resident extents,
then reproduce complete loaded bytes in ignored local storage. The static
scanner does not resolve imports or prove a complete loaded image. This metadata does
**not** establish function boundaries, sizes, shared-function identities, or
a matching build.
